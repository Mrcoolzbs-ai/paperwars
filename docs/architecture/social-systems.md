# Создание религий и идеологий до регистрации государства

## Жизненный цикл

Религия и идеология — самостоятельные сущности кампании. Игрок подаёт карточку системы до создания государства; создание государства принимает только ID существующей одобренной системы.

Карточка содержит:
- тип: `religion` или `ideology`;
- название;
- от 1 до 10 описанных верований/принципов;
- полярность каждого пункта: `positive`, `negative` или `neutral`.

Сервер проверяет максимум в десять пунктов, уникальность их названий и правило стоимости: две положительные черты бесплатны; каждая следующая положительная требует отрицательную; нейтральные бесплатны. Семантические противоречия нельзя надёжно вывести из произвольного текста программно, поэтому до выбора государства карточка проходит административное согласование.

На одну кампанию допускается до семи активных систем каждого типа, созданных игроками. Ожидающие согласования карточки уже занимают слот; отклонённая или уничтоженная система слот освобождает. Системы типа `schism` не относятся к лимиту player-created.

## Транзакции и ограничения

Все операции создания и рассмотрения блокируют строку кампании `FOR UPDATE`, затем snapshot первого хода и TurnJob в нормативном порядке блокировок. Это сериализует подачу карточек, решения администратора и регистрацию стран. Системы можно создавать и согласовывать, пока кампания остаётся в initial setup: ход 1, приём приказов закрыт, TurnJob первого хода не создан. После создания первого snapshot второй участник всё ещё может подать систему и получить решение, если страна ещё не зарегистрирована и кампания остаётся заблокированной.

Создание карточки требует активного участника без зарегистрированного государства. Новая система хранится с nullable origin, потому что место на карте ещё не выбрано. При первом назначении собственная система получает координаты точки старта. Система другого игрока выбирается только через настроенную `SocialSystemAvailabilityPolicy`; радиус и метрика географической доступности не выдумываются этим сервисом.

Только одобренные активные системы могут быть назначены официальными. Q7 сохраняется: религия и идеология могут существовать у государства на разных уровнях; это изменение не запрещает наличие обеих систем, оно ограничивает только один официальный выбор при старте.

## API

- `POST /campaigns/:campaignId/social-systems` — подать карточку; возвращает `pending`.
- `GET /campaigns/:campaignId/social-systems/mine` — посмотреть свои карточки и статусы.
- `GET /campaigns/:campaignId/social-systems/pending` — список на рассмотрение для администратора.
- `POST /campaigns/:campaignId/social-systems/:systemId/review` — `approve` или `reject`.
- `GET /campaigns/:campaignId/social-systems/available?systemType=...&spawnX=...&spawnY=...` — одобренные системы для выбора.
- `POST /campaigns/:campaignId/countries` — создать государство с `officialSystemId`; создание новой системы в этом запросе больше не поддерживается.

Администраторы задаются через переменную окружения `SOCIAL_SYSTEM_ADMIN_USER_IDS` — список UUID через запятую. Пустой список означает, что в этой инсталляции никто не может одобрить карточку; для рабочего запуска нужно назначить хотя бы одного администратора.

## Происхождение правил

Лимит семи систем каждого типа, десять пунктов, полярность и необходимость согласования восстановлены из архивного DOCX. Радиус поиска, метрика расстояния и автоматическое определение семантических противоречий в исходной спецификации не определены и здесь не вводятся.


## Личная библиотека систем (Stage 3)

- Каждая созданная игроком религия или идеология сохраняется в личной библиотеке и доступна в других кампаниях.
- Из библиотеки систему можно загрузить в редактор, изменить и сохранить либо без изменений добавить в открытую кампанию.
- Название уникально в личной библиотеке без учёта регистра. Сохранение с тем же названием обновляет старую запись.
- Внутри кампании повторное сохранение своей системы с тем же именем обновляет запись, а не создаёт дубликат.
- Новые системы автоматически доступны без одобрения. Модерационный API оставлен как задел для будущего публичного каталога; ручная модерация не входит в обычный процесс создания.
