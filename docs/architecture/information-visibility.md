# Информационная видимость и DTO-проекции

**Baseline v1.0.** Внутренние доменные модели не сериализуются напрямую в клиентские ответы.

### 7.7. DTO и информационная видимость

Серверные модели `WorldState`, `DiscoveryRecord`, `DiscoveryAccess` и `DiscoveryHistory` напрямую не сериализуются в клиентские DTO.

Каждый API endpoint использует отдельную DTO-проекцию:
- государство-открыватель видит тип находки, координаты и ход обнаружения;
- другие государства не получают скрытый результат автоматически;
- доступ проверяется по записи DiscoveryAccess со статусом `active`;
- захват клетки не предоставляет доступ;
- публичные события не содержат приватные награды или скрытые результаты;
- приватные события видны только адресованному государству;
- скрытый лор и seed не раскрываются до предусмотренного правилами действия/reveal.

Обмен разведданными — будущая дипломатическая механика; базовая модель данных поддерживает предоставление/отзыв доступа, но само дипломатическое соглашение и его условия требуют отдельной спецификации.

## Реализованные API-проекции Stage 1.9

- `GET /campaigns/:campaignId/events` доступен только активному участнику. Он возвращает публичные события кампании и приватные события, у которых `recipient_country_id` совпадает со страной участника. Идентификатор получателя не включается в DTO.
- Приватное доменное событие обязано содержать `recipientCountryId`; публичное событие не может иметь получателя. Worker проверяет контракт до сохранения, а PostgreSQL обеспечивает составной внешний ключ к стране той же кампании и ограничение согласованности видимости.
- Миграция добавляет nullable recipient для совместимости старых данных. Исторические приватные строки без известного получателя не выдаются endpoint'ом. CHECK добавлен как `NOT VALID`: неизвестный старый адресат не выдумывается, но новые записи уже обязаны соблюдать правило.
- `GET /campaigns/:campaignId/discoveries` проверяет активное членство и возвращает только находки, для которых у собственной страны есть `DiscoveryAccess.status = 'active'`. DTO ограничен полями `id`, `type`, `x`, `y`, `discoveredAtTurn`; история, payload награды, чужие идентификаторы стран и seed не возвращаются.

Эти endpoints закрывают базовую серверную фильтрацию приватных событий и уже сохранённых записей доступа к находкам. Они **не** реализуют создание находок при колонизации, выдачу/отзыв дипломатического доступа или полную проекцию всех компонентов WorldState; эти возможности остаются отдельными задачами следующих этапов.

## Обязательные свойства безопасности

- Для каждого endpoint существует явная проекция в DTO с минимально необходимыми полями.
- Карта кампании показывает принадлежность государства и spawn reservation через `isMine`, но не сериализует внутренние UUID владельцев/участников (`ownerUserId`, `userId`).
- Проверки доступа выполняются на сервере для каждой сущности и каждого запроса.
- Не полагаться на скрытие элементов только в UI.
- Скрытые находки, награды, приватные события и чужие приказы не должны утекать через вложенные объекты, списки, поиск, экспорт, ошибки или альтернативные endpoints.
- Публичный захват клетки не раскрывает содержимое находки.
- Полный seed reveal доступен только после завершения кампании.
