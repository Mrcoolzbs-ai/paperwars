# Глобальная административная панель

## Назначение и границы полномочий

Глобальный администратор — отдельное серверное полномочие, не связанное с владельцем кампании, членством в ней или модерацией социальных систем. Клиентская видимость вкладки не является контролем доступа: каждый административный API-маршрут повторно проверяет allowlist после проверки access token.

Назначение выполняется только через конфигурацию процесса API:

\`PAPERWARS_ADMIN_USER_IDS=<uuid>[,<uuid>...]\`

Для локальной настройки:
1. Создать обычную учётную запись через клиент.
2. Получить её UUID из базы: \`psql "$DATABASE_URL" -Atc "SELECT id FROM users WHERE email = lower('admin@example.test');"\`.
3. Добавить этот UUID в \`PAPERWARS_ADMIN_USER_IDS\` в локальном \`.env\` или в секреты окружения развертывания.
4. Перезапустить API и заново войти в клиент.

Не добавлять UUID в браузерный код, не принимать роль из тела запроса/заголовка и не назначать администратора по email, переданному клиентом. Для нескольких администраторов перечислить UUID через запятую. Пустое значение отключает глобальную админку.

## API

- \`GET /admin/access\` — безопасно сообщает аутентифицированному пользователю, находится ли его UUID в allowlist.
- \`GET /admin/overview\` — список всех учётных записей (только поля панели: UUID, email, статус, дата создания, число членств и стран), все кампании и счётчики.
- \`GET /admin/campaigns/:campaignId\` — игровое досье выбранной кампании: участники и страны, учения, все приказы с payload/result data, public/private events, открытия/история/доступ к находкам, экономические и боевые отчёты, метаданные snapshots и последний полный WorldState, TurnJobs/lease, RNG draws, commitments seed и последние административные события.
- \`POST /admin/campaigns/:campaignId/turn/force-close\` — досрочно закрывает указанный текущий ход. Тело содержит \`expectedTurnNumber\`; если кампания уже перешла на другой ход, операция отклоняется.

## Досрочное закрытие

Операция использует тот же порядок блокировок и транзакцию, что и обычное закрытие хода: кампания → snapshot → TurnJob → участники/приказы. Она пропускает только readiness gate (не требуется ждать подтверждения всех игроков или дедлайна).

Подтверждённые приказы переводятся в \`finalized\`; незакрытые \`draft/unconfirmed\` — в \`discarded\`. После этого блокируется приём приказов и создаётся ровно один pending TurnJob. API не запускает отдельный resolver inline: обработка остаётся задачей штатного Worker. Устаревший номер хода, завершённая кампания, уже закрытый ход, отсутствие snapshot или существующий TurnJob блокируют повторное действие.

В транзакции записывается \`admin_audit_logs\` с UUID администратора, действием, кампанией, номером хода, числом активных/подтвердивших участников и количеством финализированных/снятых приказов. При rollback аудит и закрытие вместе откатываются.

## Защита чувствительных данных

Панель намеренно не возвращает:
- password hashes, refresh token hashes, refresh-token families или access-token secrets;
- ciphertext seed, AES-GCM nonce/tag, версии encryption keys и plaintext seed;
- инфраструктурные environment variables и секреты сервера.

Seed продолжает подчиняться существующему reveal-gating кампании: админ видит commitment/status и RNG draw journal, но не получает plaintext seed до предусмотренного правилами раскрытия. Игровые приватные данные кампании (включая private events, скрытые discoveries и все report payloads) доступны только allowlisted admins, серверным маршрутом, а не обычным member DTO.

## Визуальный клиент

Вкладка «Администрирование» появляется только после \`GET /admin/access = { isAdmin: true }\`. Она показывает общую сводку пользователей/кампаний, состав игроков и кнопку раннего закрытия для активного открытого хода. JSON-секции досье раскрываются по требованию; это не меняет серверных проверок доступа.
