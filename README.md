# Paper Wars: Rebirth

Браузерная пошаговая военно-политическая стратегия. Нормативная спецификация проекта находится в [Documentation Baseline v1.0](docs/README.md).

## Текущий статус

- Documentation Baseline v1.0 и базовые инфраструктурные этапы зафиксированы в `main`.
- **Stage 1** — monorepo, PostgreSQL persistence, deterministic RNG, authentication, campaign API и контракты симуляции.
- **Stage 2 — предварительная приёмка:** клиентский вертикальный срез (авторизация, кампании, карта, основание страны, культуры и социальные карточки) предварительно завершён в draft PR #15. Полный Stage 2 не закрыт: отсутствуют приглашения второго игрока, обязательная административная модерация, приказы, закрытие/исполнение ходов и двухпользовательский end-to-end.
- **Stage 3 — browser client (MVP)** — вход/регистрация, создание и подключение к кампании по UUID, воспроизводимая генерация мира по seed, интерактивная карта, стартовая территория 5×5 с минимум семью клетками суши, учения, культура/форма правления, загрузка флага/эмблемы и основание государства с семью стартовыми постройками. После основания показываются карточки страны и официальной веры/идеологии; постройки видны на большой карте, культура показана символами с подсказками названия и описательного эффекта.
- Seed можно задать вручную или получить автоматически. Один и тот же seed и размер карты всегда дают один и тот же рельеф/реки. Вода и реки имеют единый цвет.
- Вместимость кампании рассчитывается как `floor(ширина × высота / 100)`. В списке показываются текущие/максимальные игроки; игрок может покинуть кампанию, после чего она пропадает из его списка и слот освобождается.
- Добавлено отдельное лобби открытых кампаний: игрок видит миры, в которых ещё есть свободные места, и может вступить напрямую без ручного ввода UUID. Вступление повторно проверяет сервер с блокировкой кампании.
- Карта использует нерегулярные континенты, береговые линии и реки, генерируемые из seed. Белые клетки — суша, синие — вода/реки, чёрные линии — сетка. Зарегистрированные территории и резервации точек старта читаются из API кампании.
- В текущей ветке PR #15 новые религии/идеологии пока доступны без обязательной модерации. Это известное расхождение с нормативным Baseline: утверждённое правило требует административного согласования до назначения официальной системой.
- Клиент работает как статические HTML/CSS/JS-файлы и отдаётся тем же Fastify-сервером. Отдельный frontend build и Docker для запуска не нужны.
- После основания доступно ограниченное действие MVP: немедленное строительство дополнительной фабрики, поля, научного центра, храма, казарм или башни на свободной сухопутной клетке своей территории 5×5. Сервер проверяет владение клеткой, рельеф, занятость и население, списывает одного жителя, записывает событие и обновляет snapshot. Действие пока не расходует ОД и не является частью автоматической обработки хода.
- Перенос столицы, колонизация, снос, армия, дипломатия, экономика и полноценные игровые эффекты приказов ещё не реализованы. Generic turn queue/Worker и контракты приказов существуют, но отдельный production Worker не запускается, пока нет утверждённого полного resolver для игровых фаз.

Спецификация и код не означают, что игра уже исполняет полный ход. Q18–Q20 остаются сюжетными PROPOSAL и не входят в канон.

### Текущий технический инкремент

Stage 1.7: pure Simulation Engine уже проверяет совместимость snapshot/ruleset, допускает только finalized orders, вызывает подключённый resolver и сам ведёт RNG-журнал. Это не реализация конкретных экономических, боевых или иных игровых механик. Следующий инфраструктурный шаг по roadmap — Stage 1.8 (`closeOrders` и PostgreSQL Worker).

## Структура

- `apps/api` — HTTP API и раздача браузерного клиента.
- `apps/web/public` — клиент Paper Wars (vanilla JavaScript, HTML и CSS).
- `packages/shared` — общие типы и утилиты.
- `packages/domain` — доменные контракты.
- `packages/world` — старт государства, территории и социальные системы.
- `packages/simulation` — pure turn orchestration, проверка contracts и журналирование RNG; конкретные игровые фазы и persistence finalization ещё впереди.
- `packages/persistence` — PostgreSQL/Drizzle persistence и миграции.
- `tests` — smoke и интеграционные тесты.
- `docs` — Documentation Baseline v1.0 и roadmap.

## Требования

- Node.js 22 или новее.
- Corepack и pnpm 9.15.x.
- PostgreSQL 18 или новее.
- Docker Desktop не обязателен: PostgreSQL можно установить как обычную службу Windows.

## Windows: запуск без Docker

1. Обнови файлы клиента скриптом `update-paperwars-web-client.bat` (для уже скачанной старой копии проекта).
2. Если окно `Paper Wars API` уже открыто, закрой его, чтобы остановить старый процесс сервера.
3. Убедись, что PostgreSQL запущен и настройки `DATABASE_URL` в `.env` соответствуют локальной базе.
4. Запусти `start-paperwars-postgresql19.bat` двойным щелчком. Скрипт применит миграции, соберёт проект, проверит версию API и откроет браузер на `http://127.0.0.1:3000`.

Первая установка Node.js и PostgreSQL выполняется отдельно. Скрипт запуска не меняет существующий `.env`. Окно `Paper Wars API` должно оставаться открытым, пока используешь игру.

## Ручная установка и запуск

```bash
corepack pnpm install
cp .env.example .env
corepack pnpm --filter @paper-wars/persistence db:migrate
corepack pnpm --filter @paper-wars/api dev
```

Главная страница игрового клиента: `http://127.0.0.1:3000/`.

Health-check API: `http://127.0.0.1:3000/health`.

## Проверки

```bash
corepack pnpm format:check
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
corepack pnpm build
```

GitHub Actions поднимает отдельный PostgreSQL service и выполняет миграционные integration tests автоматически.

## Социальные системы и модерация

В одной религии/идеологии выбирается от 1 до 10 пунктов. Первые два позитивных пункта бесплатны; каждый следующий позитивный балансируется негативным; нейтральные не влияют на баланс. Каталог религий и идеологий различается. В текущей ветке PR #15 новые системы пока автоматически получают статус approved; это известное временное расхождение с Baseline, который требует административного согласования до назначения официальной системой.

При выборе официальной системы игрок видит свои учения и до трёх ближайших учений того же типа. Ближайшие системы определяются сервером по квадрату евклидова расстояния между зарезервированными точками старта.

Картинки гербов/флагов принимаются как PNG, JPEG или WebP размером до 512 КиБ. Культура ограничена пятью выбранными чертами; форма правления выбирается из каталога.

## Если не получается войти или зарегистрироваться

- Пароль должен содержать не менее 12 символов/UTF-8 байт.
- Открывай игру по одному адресу: `http://127.0.0.1:3000`; не переключайся между `localhost` и `127.0.0.1` в процессе работы.
- Если старый процесс API всё ещё занимает порт 3000, обновлённый BAT-лаунчер сообщит об этом. Закрой старое окно `Paper Wars API` и запусти лаунчер повторно.
- Если авторизация прошла, но список кампаний не загрузился, игра оставит пользователя в системе и покажет отдельную ошибку загрузки кампаний вместо возврата к форме входа.

## Текущие ограничения клиента

- Генератор создаёт детерминированные континенты и реки, но пока не моделирует высоты, биомы, климат, озёра и полноценную гидрологию. Территории стран и точки старта берутся из базы кампании.
- Численные эффекты принципов пока предварительные и не применяются к расчётам симуляции. Их балансировка отдельно отмечена в `docs/roadmap.md` до подключения к экономике/обществу.
- Выбор длительности хода сохраняется в кампании и задаёт первый дедлайн после завершения основания государств. Автоматического worker, который исполняет ход по дедлайну, пока нет.
- Полный цикл «приказ → worker → симуляция → snapshot → API» ещё не достигнут.
- Invitations/roles, audit trail и rate limiting для публичных auth endpoints остаются отдельными задачами.

## Seed encryption configuration

Copy `.env.example` to `.env` for local development. The included `dev-v1` key is a public placeholder and must never be used for deployed or production campaigns. Production keys must be supplied through a protected environment, Docker secrets, Vault or KMS; never commit real key material. Keep every historical key version available until all campaigns encrypted with it have completed and their seeds have been revealed.
